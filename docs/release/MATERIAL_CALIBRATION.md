# Material purchase quantities and arithmetic

The audit found that the existing list displayed takeoff numbers without units (for example, hundreds of linear feet looked like hundreds of boards), described all unit prices as each, and priced the net fastener quantity instead of the full boxes needed. Quantity-basis text could also omit its claimed waste in the numeric total.

New planning responses include a bounded arithmetic-only quantityFormula. The server calculates it with a small parser, never JavaScript evaluation; units, functions, implicit concatenation, nonfinite values and excessive depth/size are rejected. Numeric inputs remain design assumptions to verify, not measurements recovered from a photo. The prompt requires explicit input/waste bases, matching stock dimensions and package coverage, one provisional material choice honoring preferences, and prices per the same quantity unit. It excludes kit double-counting and unsupported anchoring assumptions.

The portable purchase calculator is identical in server and mobile source. Known whole boards/sheets/boxes/rolls/kits round up before pricing; measured bulk retains fractional quantities. For example, 800 screws sold in boxes of 350 at an $0.08 per-screw allowance means 3 boxes at $28 and an $84 purchase allowance. A takeoff of 13×14 ft plus 10% waste is 200.2 ft, requiring 15 fourteen-foot boards; at $1.15 per ft the stock allowance is $241.50. Unknown prices remain unpriced. New saved budget ranges use those purchase totals and carry estimateBasisVersion=purchase-packages-v1. Legacy data remains readable; a user can apply a new estimate to a saved image without another token or design revision.

The mobile list displays purchase quantities with units and matching line prices. Material details separate required takeoff from purchase packages and use the actual pricing unit. This is still a reference USD estimate, not a live retailer quote, a verified cut list or a certified structural design. No retailer-pricing API or new payment configuration was introduced.

Validation includes exact package/stock rounding, fractional bulk, unknown prices, arithmetic/waste/area-volume conversions, unsafe formula rejection, shared client/server price contracts and cost-range reconciliation. Existing catalog/step validation, bounded correction, user consent, paid access and plan-only retry behavior remain enforced.

TypeScript, ESLint, all 94 service tests and the production build pass. The mobile calculator matches this file exactly and passes the shared purchase examples. Actual provider output with the new calibration instructions still requires a user-generated or refreshed plan; these checks do not establish live retailer-price accuracy. The preceding missing-plan recovery was separately confirmed on the owner's real project with eight materials, ten phases, no additional token charge and all three revisions retained.
