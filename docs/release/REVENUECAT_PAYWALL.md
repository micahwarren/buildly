Owner-approved one-time packs: **1 project token for US$2.99**, **2 for US$4.99**, and **4 for US$8.99**. Each token includes the initial AI design/materials/plan and **three successful design revisions**. There is no subscription. The app displays the localized StoreKit price returned through RevenueCat; web shows explicitly labeled US reference prices without checkout.

## Implemented

- Native RevenueCat React Native SDK 10.16.0 in the active Expo app, not the archived Capacitor client. Checkout uses the authenticated account; account switches serialize with the store sheet. Cancellation, deferred/network-uncertain results, persistent purchase checks, restore, and server balance refresh are handled separately.
- Three offer cards with original construction-token artwork, warm price buttons, restrained depth and actual per-token savings appear left to right in 1/2/4 order. The app fixes that display order independently of RevenueCat's returned package order. All cards remain visible when tokens are already owned; repeat purchases add to the balance. Checkout stays open after a confirmed purchase. A separate Use a project token action resumes the saved idea. Closing preserves the draft. Native checkout prices always come from StoreKit.
- My projects replaces the project-count badge with the authenticated server token balance and a tap target for the token shop. Balance refreshes on focus, resume, pull-to-refresh and shop close; stale results from another account are discarded. Settings also opens Project tokens.
- Only verified server-side RevenueCat events add credits. Events are constrained by store, product, configured RevenueCat app, environment and a secret webhook authorization header. Duplicate purchases/refunds are idempotent. Deleted accounts do not regain credits from late notifications.
- Credit/revision reservations and refunds are atomic and service-role-only. Each verified pack receipt owns 1/2/4 individual token allocation rows. A design reserves one of those units, then finalizes it at the durable image checkpoint. Failure releases exactly that unit; stale cleanup reconciles saved results. A pack refund removes only its unused units and blocks further revisions funded by that pack, preserving unrelated tokens and saved designs. Legacy single receipts and RPC calls remain compatible; the live migration preserved existing balances, receipts and project access.
- RevenueCat customer email is synchronized from the signed-in account for **admin/customer lookup only**. Emails are metadata, never authorization or purchase IDs. No public people-search endpoint was added.
- In-app/public privacy and terms describe Apple/RevenueCat processing, one-time credits, revisions, failures, restoration and deletion. Account deletion warns about unused credits when purchases are enabled.
